# Social Eval — PDF Specification & JSON Schema

The PDF is generated by `scripts/build_report.py`.
It reads a single JSON file and produces a branded A4 PDF.

---

## Top-level JSON structure

```json
{
  "month": "May 2026",
  "generated_date": "2026-05-16",
  "sections": [
    { "id": 1, "title": "Executive Summary",                "content": [ ... ] },
    { "id": 2, "title": "Account Snapshot",                 "content": [ ... ] },
    { "id": 3, "title": "Reels Performance Deep-Dive",      "content": [ ... ] },
    { "id": 4, "title": "What's Working",                   "content": [ ... ] },
    { "id": 5, "title": "What's Not Working",               "content": [ ... ] },
    { "id": 6, "title": "Competitor Intelligence",          "content": [ ... ] },
    { "id": 7, "title": "Competitive Benchmarking & Recommendations", "content": [ ... ] }
  ],
  "appendix_a": {
    "title": "Competitor Snapshot",
    "table": {
      "headers": ["Account", "Est. Followers", "Posts/Week", "Dominant Theme", "Brand Tone", "Key Differentiator"],
      "rows": [ ... ]
    }
  }
}
```

**Notes:**
- Section 1 is placed first in PDF regardless of array order (script sorts by id, with id=1 first)
- `generated_date` is ISO format YYYY-MM-DD
- `appendix_a` is optional — omit if no competitor data was found

---

## Section object

```json
{
  "id": 2,
  "title": "Account Snapshot",
  "content": [ /* array of block objects */ ]
}
```

## Content block types

### paragraph
```json
{ "type": "paragraph", "text": "Your paragraph text here. (Source: Windsor.ai Instagram connector, accessed 2026-05-16)" }
```
Source citations use `(Source: ...)` inline — the script converts these to `[N]` superscripts
and builds a numbered references block at the end of each section.

### heading
```json
{ "type": "heading", "text": "Instagram Performance", "level": 2 }
```
Level 2 = purple H2 with rule above. Level 3 = dark grey H3.

### bullets
```json
{
  "type": "bullets",
  "heading": "What's driving high performance",
  "items": [
    "Chef Story reels achieve 2.3× avg ER% vs Food Visual reels (Source: Windsor.ai, 2026-05-16)",
    "Reels published Tuesday–Thursday outperform weekend posts by 34%"
  ]
}
```
`heading` is optional. Items support inline `(Source: ...)` citations.

### table
```json
{
  "type": "table",
  "headers": ["Reel", "Date", "Plays", "ER%", "Saves"],
  "rows": [
    ["Chef Priya's Chettinad...", "2026-04-12", "18,400", "8.2%", "312"],
    ["Morning dabba prep...",    "2026-03-28", "14,200", "6.9%", "218"]
  ]
}
```

### callouts
Yellow stat card boxes — use for the key KPIs at the top of Section 2.
```json
{
  "type": "callouts",
  "items": [
    { "number": "42",    "label": "Reels Published (90 days)" },
    { "number": "5.8%",  "label": "Avg ER% Instagram" },
    { "number": "3.1%",  "label": "Avg ER% Facebook" },
    { "number": "+1,240","label": "Follower Growth (30 days)" }
  ]
}
```
Up to 4 items per callout row. Use 3 or 4 for best visual balance.

### note
```json
{ "type": "note", "text": "Windsor.ai returned aggregate data only — post-level metrics not available for this pull." }
```
Rendered in italic grey. Use for data limitations and methodology notes.

### risk
```json
{ "type": "risk", "text": "Competitor engagement estimates are based on public profile observation only — treat as directional, not audited." }
```
Rendered as a yellow-bordered warning box. Use sparingly (1–2 per report max).

### page_break
```json
{ "type": "page_break" }
```

## Charts (auto-inserted by section)

Charts are hard-coded into the script and auto-appended after section content.
You do NOT need to include chart blocks in the JSON — the script handles them.

| Chart | Section | Description |
|---|---|---|
| Chart A | 2 | 90-day reach + engagement trend (dual-axis line) |
| Chart B | 3 | Top 10 reels by engagement rate (horizontal bar) |
| Chart C | 3 | Engagement by content theme (grouped bar) |
| Chart D | 4 | Posting frequency by day-of-week (bar) |
| Chart E | 7 | Competitor engagement rate comparison (grouped bar) |
| Chart F | 7 | Content strategy radar (polar: 6 themes, 3 players) |

Charts are populated from data in the JSON — see "Chart data fields" below.

## Chart data fields (top-level in JSON)

The build script reads these top-level fields to populate charts.
Include them alongside `sections`:

```json
{
  "month": "May 2026",
  "generated_date": "2026-05-16",

  "chart_a_data": {
    "dates": ["Mar 1", "Mar 15", "Apr 1", "Apr 15", "May 1", "May 15"],
    "reach":  [12000, 15400, 18200, 14300, 21000, 19800],
    "er_pct": [4.2, 5.1, 6.8, 4.9, 7.2, 6.1]
  },

  "chart_b_data": {
    "labels": ["Chef Priya Chettinad...", "Morning dabba prep...", "..."],
    "er_pct": [8.2, 6.9, 6.4, 5.8, 5.6, 5.1, 4.9, 4.7, 4.2, 3.8]

    "days":    ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"],

  "chart_e_data": {
```

If chart data is unavailable (Windsor.ai returned no post-level data), omit the relevant
chart data fields — the script will skip those charts gracefully and insert a note instead.

## Source citation format

In any `text` or `items` string:
```
Some finding (Source: Windsor.ai Instagram connector, accessed 2026-05-16)
```
The script converts this to `[N]` in the body text and builds a numbered references
block at the bottom of each section. Multiple sources in one section are numbered
sequentially. Identical source strings reuse the same number.
